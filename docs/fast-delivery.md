# 10분 이내 지원 처리 — 2026-09-17

자동지원 대상은 최초 발견부터 발송까지 10분 이내, 사용자가 검수한 지원은 발송 승인 이후 1분 내 작업 시작을 목표로 한다. 원문은 게시일만 제공하므로 실제 게시 시각부터의 정확한 지연을 보장하지 않는다. 지정양식·사이트 접수·읽기 실패는 발송 대신 확인 사유를 표시한다. 검수 모드의 사용자 대기 시간은 시스템 지연에 포함하지 않는다.

## 실행 경로

- Pages가 승인과 첨부 목록을 DB에 저장한 뒤 인증된 cron Worker `/wake`를 호출한다. 승인 저장 실패 시 호출하지 않으며, 호출 실패가 이미 저장된 승인을 되돌리지 않는다.
- 분석 작업은 공고별 지원 준비 직후 `delivery.yml`을 요청한다. 다른 공고와 재시도를 기다리지 않는다. `resume.yml`은 준비·안내 작업만 담당한다.
- `delivery.yml`은 준비·안내를 거치지 않고 `career_claim_resume_send`로 승인된 항목만 가져와 발송한다. 발송 전 원문·동의·버전·수신처·첨부 검증과 테스트 계정 단일 수신처 정책을 유지한다.
- Cloudflare 타이머는 매분 DB 작업 상태를 확인한다. 미처리 분석/준비/발송을 각각 요청하고, 실행 중인 동일 작업은 추가 요청하지 않는다. 한 트리거가 실패해도 나머지 트리거는 실행한다.
- 수집은 매분 각 원문 분류의 최신 20개를 확인한다. 10분 단위에는 전체 목록을 조회하고 기존 내용 갱신·내려간 공고 판단·법인 동기화·정리를 수행한다. 부분 수집 결과로 기존 항목을 덮어쓰거나 제거하지 않는다. 전체 점검 완료 시각은 DB에 기록하므로 예약 실행이 취소돼도 다음 회차가 전체 점검을 수행한다.
- AI 큐와 발송 직전 재검증의 모델 응답 대기는 45초로 제한한다. 큐 재시도는 DB에 남겨 다음 실행에서 이어간다. 전송 결과 불명확 항목은 자동 재발송하지 않는다.

## 관측

`career_analysis_jobs`의 `enqueued_at/started_at/completed_at`, 지원 상태 이벤트, `approved_at/sent_at`으로 구간별 시간을 확인한다. 비공개 `career_pipeline_health`에는 마지막 1분 점검과 대기 시간·10분 초과 건수를 저장한다. 7분 초과는 Worker 경고 필드, 10분 초과는 기존 관리자 알림 경로(설정되어 있는 경우, 10분 회차)를 사용한다. 시간 지연이 외부 실행 환경·원문·메일 서비스에 좌우되므로 목표 달성률은 운영 표본으로 검증해야 한다.

## 배포

1. `030_fast_delivery.sql` 적용.
2. 임의 생성한 동일 `CAREER_DISPATCH_SECRET`을 Pages production과 cron Worker에 저장. Pages에 `CAREER_WAKE_URL=https://cpaping-cron.ohshsh00.workers.dev/wake` 저장.
3. GitHub 워크플로·Pages 배포 후 cron Worker 배포. 기존 GitHub 토큰은 Worker 안에만 유지하며 브라우저로 전달하지 않는다.
4. 공개 요청의 내부 API/깨우기 접근 거부, 매분 건강 상태 갱신, 기존 승인된 발송의 처리를 확인한다. 임의의 새 지원 승인이나 사용자 자동지원 모드 변경은 하지 않는다.
