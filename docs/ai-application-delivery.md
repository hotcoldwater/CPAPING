# 공고 요건과 지원 발송

- 공개 공고와 첨부·지원 링크만 Kimi API로 분석한다. 지원자 파일이나 개인정보를 보내지 않는다.
- `career_requirement_analyses`는 원문·읽기 실패 상태·분석 버전의 해시로 재사용한다. 공고 내용이 바뀌면 공개 분류가 초기화되고 예약 작업이 다시 분석한다. 발송 직전 원문과 연결 요건을 재확인한다.
- 신규 등록은 PDF와 DOCX를 함께 저장한다. 지정 형식이 없으면 PDF, DOCX만 요구하면 Word 원본을 사용한다. 내용 변환이나 확장자 바꾸기는 하지 않는다.
- 지정 제목에는 저장된 이름·출생연도·합격연도를 사용할 수 있다. 필요한 정보가 없거나 원문 근거와 일치하지 않으면 확인 필요로 중지한다.
- 지정 지원서, 사이트 접수, 미확정 요건, 발송 오류는 사용자 알림 outbox와 지원 이력에 남긴다. 관리자 검수 절차는 없다.
- 메일 지원은 해당 지원에서 제목·본문·첨부 이름 및 파일을 수정한 뒤 명시적으로 보낼 수 있다. 사이트 접수와 전송 결과 불명은 재발송 버튼을 제공하지 않는다. 발송 결과 불명은 보낸편지함 확인이 필요하다.
- 모든 파일은 교체 후에도 보존된다. `career_application_events`는 상태/작성 버전, `career_mail_deliveries.attachments`는 실제 제출한 파일 ID·이름·MIME·해시를 보관한다. 합격 결과는 해당 delivery와 연결된다.

## 테스트 수신자 정책

`career/routing.py`의 서버 정책은 로그인 `ohshsh00@gmail.com`과 확인된 사용자 UUID를 `leorich21@naver.com`으로 고정한다. 최초 지정한 integer0125 주소는 사용자의 정정으로 대체했다. 발송 이력은 원래 담당자와 실제 수신자를 별도 저장한다. `mail.send`에서 다시 정책을 적용하고 MIME을 새로 만들므로 자동/검수/수동/테스트 어떤 경로에서도 CC/BCC를 추가할 수 없다. 다른 로그인 계정은 서버 인증 조회가 성공해야 원래 수신자로 보낸다. 정책은 사용자 해제 요청 전까지 유지한다.

지원 준비·실패 안내는 지원 메일과 다른 서비스 알림으로, 등록된 사용자 이메일로 보낸다.

## 운영

- DB migrations 025, 026을 먼저 적용한다.
- GitHub secret `KIMI_API_KEY`를 설정한다. 기본 모델 `kimi-k2.6`.
- `application-analysis.yml`은 15분 간격으로 미분류 공고를 최대 10건, 배치당 4건 분석한다. 내용 수정 시 자동 재분석된다.
- `resume.yml`은 5분 간격으로 준비/검수 안내/발송/실패 안내/답장 확인을 처리한다.
- AI 호출 간격은 21초 이상이고, 429/5xx는 분석 요청만 제한적으로 재시도한다. 실제 이메일은 자동 재시도하지 않는다.
- 사이트가 첨부 다운로드를 거절하거나 내용을 읽을 수 없으면 확인 필요로 남긴다.
