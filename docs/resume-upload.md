# 완성 이력서 업로드 지원 — 2026-09-14

사용자 결정: 자소서 기능을 보류하고 상단 탭에서 제거한다. 사용자가 완성한 이력서를 업로드하고 개인 계정에서 그대로 첨부 발송한다. Kimi/OpenAI 설정·평가는 현재 작업 범위에서 보류한다.

## 사용자 흐름

상단 탭은 공고 / 법인 / 게시판이다. 마이페이지 → 내 지원현황에서 이력서·자동지원 설정을 펼친다. PDF·Word(.docx), 암호 없는 3MB 이하 파일을 올리고 사용할 파일과 이름·메일 제목·본문을 저장한다. {이름}·{법인}·{공고}만 실제 값으로 바꾸며 이력서 내용과 파일명은 수정하지 않는다.

원하는 법인, 지역, 지원 자격, 고용 형태, 경력, 최신 공시 매출 범위, 포함/제외 키워드로 범위를 정한다. 매출 자료가 없는 법인은 매출 조건 설정 시 제외한다. 관심 법인을 고르거나 법인 제한 없이 검색을 명시적으로 선택한다. 특정 법인에 맞춘 파일은 그 법인만 선택한다.

발송 방식은 기본 '내가 검수하고 보내기', 신규 공고 검색도 기본 꺼짐이다. '조건에 맞으면 자동 발송'을 고르고 이력서 확인·자동 발송 동의를 해야 해당 방식으로 저장할 수 있다. 실제 이력서 업로드·개인 조건 저장은 사용자가 수행한다. 관리자가 회원 대신 이를 켜지 않는다.

새 공고 지원은 설정 저장 이후 처음 발견한 공고만 대상으로 하고 기존·끌올 공고는 제외한다. 기존 공고는 상세의 '내 이력서로 지원 준비'를 눌러 선택한다. 수동 선택은 항상 검수하며, 같은 원본 공고에 중복 지원하지 않는다.

## 자동으로 발송하는 범위

최신 한공회 원문에서 자유양식 이력서·이메일 제출이 명확하고 수신 주소가 하나이며 별도 제목·파일명·지정 양식·추가 서류 등의 신호가 없는 공고만 자동 발송한다. 해당 신호가 있으면 검수, 수신 주소가 없거나 파일이 잘못됐으면 보류한다. 규칙 기반 검사로 임의의 공고 내용을 완전히 이해한다고 주장하지 않는다.

검수 화면에서 원문, 허용된 수신 주소, 제목·본문·첨부를 확인한다. 별도 양식이나 추가 서류 요구를 현재 파일이 충족하는지 사용자가 확인해야 한다. 파일 교체가 필요하면 새 파일을 올려 선택한 뒤 '현재 이력서로 다시 준비'한다. 파일 여러 개 첨부와 지정 양식 자동 작성·변환은 현재 범위에 포함하지 않는다.

발송 직전 최신 공고·마감·수신 주소·이력서 해시·발신 계정·지원 조건 버전을 다시 확인한다. 원문이나 설정이 바뀌면 보내지 않고 보류한다. 새 이력서 업로드나 조건 변경·중지 시 기존 대기를 검수 상태로 돌리고 버전을 증가시킨다. 이미 외부 전송 중인 메일은 취소할 수 없다.

지원 준비 → 검수 필요/발송 대기 → 발송 중 → 발송 접수 순서다. 실패·결과 불명도 표시하며 접수 결과 불명은 자동 재발송하지 않는다. 실제 발송 전 이력 저장, 같은 지원서 버전 유일성, 원본 공고당 회원별 유일성으로 중복을 막는다. 내 지원현황의 기존 발송 이력과 읽음 추정은 유지한다. 열람 이미지 신호는 실제 담당자의 독서나 채용 접수를 보증하지 않는다.

## 보관과 기존 자료

업로드 파일은 본인 전용 DB에 보관하고 한 회원당 최대 20개다. 파일은 변경하지 않으며 새 업로드는 새 파일로 저장한다. 현재 설정이나 발송·지원 이력에서 사용 중인 파일의 단독 삭제는 막아 당시 첨부를 보존한다. 사용하지 않는 파일은 삭제할 수 있고, 전체 작성공간 삭제 API 또는 회원 탈퇴 시 관련 자료를 삭제한다. 자소서 입력·AI 작업 API는 보류 상태로 차단하며 기존 작성 자료를 삭제하지 않는다. `/essay/`는 보류 안내와 내 지원현황 링크만 제공한다.

이력서와 메일 문구를 AI API에 전송하지 않는다. 업로드 시 크기·확장자·서명을 확인하고 준비 단계에서 실제 PDF/Word 구조·암호·손상을 확인한다. 검증 과정에서 문서를 재생성하지 않는다. 발신은 연결한 개인 Gmail이며 CPAPING 공용 메일 계정을 사용하지 않는다.

## 실행·검증

운영 DB에는 SQL 017을 014·016 이후 적용한다. 이력서 업로드·조건 저장·중지는 회원 단위 DB 잠금과 상태 버전 검사로 동시 변경을 처리한다. 서버 전용 RPC는 anon/authenticated가 직접 호출할 수 없다.

`career/resume_runner.py`는 AI 처리와 독립적이다. GitHub Actions `resume.yml`이 5분 주기로 준비·발송하며 대기시간이 추가될 수 있다. `CAREER_RESUME_ENABLED`와 `CAREER_SEND_ENABLED`를 각각 켜야 작업·실제 발송이 가능하다. 사이트 서버에는 `CAREER_RESUME_ONLY=true`, `CAREER_RESUME_ENABLED=true`, 기존 AI 작업·기존 전체 지원 API는 비활성화한다. Google 인증과 같은 MAIL_TOKEN_KEY를 작업 서버에 설정한다.

검증: 업로드 위조·다른 사용자 접근·SQL 권한·동시 상태 변경·자동 중지·원문 외 수신자 거부·파일명 HTML 무해화, 자동/검수 분리·첨부 원본 바이트 보존·원문 변경/마감 차단·결과 불명 재시도 금지 검사. 메일은 모의 발송으로 검증한다. 이번 변경에서 추가 실제 테스트 메일은 보내지 않았다. 실제 이력서는 사용자가 업로드하지 않아 본인 이력서의 종단 발송은 남아 있다.

실제 공개 데이터로 법인 255곳·공고 상세 69개·338개 공통 상단바를 빌드해 자소서 탭 제거와 지원 버튼을 확인했다. 브라우저 실제 시각 검수와 사용자의 업로드·조건 저장 확인은 별도다.

후속 검증: 실제 최신 공고 원문 조회·수신 주소 후보·검수 사유 추출 확인. SQL 017 운영 적용 후 신규 서버 전용 함수 권한을 확인한다.
