# 내 지원현황·읽음 추정·탐색 구조 — 2026-09-13

사용자 요청: 개인 Gmail에서 지정한 담당자 테스트 주소로 테스트 지원 메일 발송, 법인 열람 여부 표시, 공고/법인/자소서/게시판 탭, 마이페이지에서 내 지원현황/내 정보 선택.

## 구현과 표시 기준

- 공통 빌드 후처리로 모든 상단바의 탭과 마이페이지 메뉴를 통일한다. 내 정보는 기존 `/account/`, 내 지원현황은 `/applications/`다. 메뉴는 키보드와 모바일에서도 선택할 수 있다.
- `/essay/`에서 엑셀 기반 네 시트·24질문과 최종 자소서를 저장할 수 있다. Kimi 잔액 조회는 성공했지만 available/voucher/cash 모두 0이었다. AI 작업·문서 생성·자동지원 설정은 현재 서버에서 차단하고 준비 중 안내를 표시한다. 유료 호출은 하지 않았다.
- 발송 이력은 회원 전용 테이블 `career_mail_deliveries`에 보관한다. 발송 방식(자동/검수 후/테스트), 대상 법인, 수신 주소, 제목·본문·첨부파일, 접수 상태, 최초 열람 신호 시각을 표시한다. SQL 016은 014 이후 적용하며 게시판 SQL 015와 독립적이다.
- 발송 전에 이력을 저장하고 지원서 ID+검수 버전 또는 테스트 키의 유일성으로 중복 발송을 막는다. 접수 결과가 불명확하면 자동 재발송하지 않는다.
- 읽음 표시는 **읽음 추정 / 확인 안 됨**이다. 개인 Gmail에는 공식 수신확인 기능이 없고, 열람 이미지가 불러와진 사실만 확인한다. 자동 로딩·이미지 프록시·보낸편지함 미리보기·전달이 오탐을 만들 수 있고 이미지 차단은 누락을 만든다. 담당자 본인이 읽었는지 확정하지 않는다.
- 수신 메일에 열람 확인 이미지 포함 사실을 안내한다. 추적용 값은 무작위 32바이트이며 DB에는 해시만 저장한다. 최초 신호 시각만 기록하고 IP·User-Agent·위치는 이력에 저장하지 않는다. 미리보기 화면에는 추적 이미지를 삽입하지 않는다. 알려지지 않은 토큰과 정상 토큰은 같은 이미지 응답을 반환한다.
- 이력 및 파일은 로그인한 본인만 API로 조회한다. 회원 탈퇴 시 이력을 삭제하고 작성공간 삭제에도 이력을 포함한다. 개인 메일 연결 해제만 하면 기존 이력은 유지한다.

## 테스트 발송

사용자가 지정한 수신 주소에 한 건만 보낸다. `[CPAPING 테스트] 회계법인 입사지원 — 테스트 지원자` 제목과 가상 지원자 PDF를 사용하며 실제 채용 지원이 아님을 명시한다. 발송 도구는 `scripts/test-personal-mail.py`이며 기본은 미리보기, `--send`를 지정한 경우만 발송한다. 같은 `--test-key`로 재실행해도 이미 시도한 메일은 다시 보내지 않는다.

## 검증

Gmail 기존·추가 API 테스트 18개, Python 이력·MIME 테스트 5개, SQL 권한·중복·최초 신호 기록, 화면의 HTML 무해화·메뉴 순서·키보드 동작 검사 통과. 빌드된 338개 상단바와 개인 화면의 GA/Clarity 미삽입을 확인했다. 실제 수신과 네이버에서 열람한 이후의 신호는 테스트 발송 뒤 사용자가 확인할 단계다.

## 사용자 다음 단계

1. Kimi 플랫폼 로그인 → 결제/잔액 메뉴에서 결제수단 등록 및 API 잔액 충전 → 준비됐다고 알리기. 단가와 모델을 확인하고 합성 자료로 제한된 품질 평가를 진행한다.
2. 테스트 수신 계정에서 메일 도착과 PDF 첨부파일 확인. 이후 내 지원현황에서 열람 상태 새로고침. 감지되지 않으면 사용 중인 메일 앱·외부 이미지 표시 여부를 확인한다.
3. 자소서 탭에 본인 자료를 입력하고 저장. 생성 기능이 열리면 실제 문체·사실 충실성·수정 시간을 함께 평가한다.
