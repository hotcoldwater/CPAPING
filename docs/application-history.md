## 편집·발송

- 검수필요: 준비된 첨부파일을 보여주며 삭제·추가·파일명 수정 가능.
- 확인필요: 이유를 표시하고 첨부파일은 비워둔다. 사용자 이름과 법인이 치환된 제목·본문을 편집하고 파일을 업로드한다.
- 승인 API는 전송 대기에 넣는다. 실제 공급자의 접수 성공 뒤에만 지원완료와 메일 지원일이 표시된다. 대기·전송 중에는 처리 안내를 표시하고 상태 수정을 막는다.
- 발송 결과 불명확: 보낸편지함에서 미발송 확인을 명시한 뒤에만 수동 재발송을 허용한다. 자동 재시도하지 않는다.
- 사이트 접수: 외부 사이트 이동, 직접 상태 변경, 실제 지원일 입력. 이메일은 발송하지 않는다.
- `ohshsh00@gmail.com`의 모든 지원 메일 실제 수신자는 계속 `leorich21@naver.com` 단일 주소다. 최종 전송 단계의 서버 정책을 유지한다.

## 결과 기록과 이력

- 상태: 검수필요, 확인필요, 지원완료, 서류합격, 최종합격, 불합격.
- 상태 버튼에서 직접 기록·정정한다. 상태 변경만으로 메일을 발송하지 않는다.
- `manual_status`는 실제 전송 상태와 분리한다. 사이트 지원일도 `site_applied_on`에 저장하며 `sent_at`을 만들거나 바꾸지 않는다.
- 행 잠금과 버전 검사로 다른 창/발송 작업과의 충돌을 차단한다. 사용자 소유권은 인증 계정 기준으로 강제한다.
- 결과의 답장 자동 판별을 중단했다. 이전 작업이 뒤늦게 실행되어도 DB가 메일 기반 결과 변경을 무시한다. 이전 자동 판별 값은 새 상태 표시의 근거로 사용하지 않는다.
- Gmail 신규 연결은 발송 권한만 요청한다. 기존 연결과 발송 권한은 유지한다.
- 파일과 발송별 첨부 명세를 보존하며 수동 결과·지원일 변경도 이벤트로 남긴다. 상태 정정으로 실패 알림이 중복 생성되지 않는다.

## 수집 즉시 분석 — 2026-09-17

- 공고 저장 트리거가 `career_analysis_jobs`에 작업을 등록하고, 크롤러가 저장 직후 `application-analysis.yml`을 호출한다. 별도의 15분 분석 예약은 제거했다. 원문 변경도 새 분석 작업을 만든다.
- 크롤러에는 GitHub 작업 실행 권한만 추가한다. 분석 작업 실행에 실패하면 DB의 미처리 작업이 남아 다음 수집에서 다시 실행을 요청한다. 수집기는 AI 응답을 기다리지 않는다.
- 작업자는 행 잠금·실행 식별자로 중복 처리를 막고, 원문이 변경된 뒤 도착한 오래된 분석 결과는 폐기한다. 중단된 작업은 7분 후 회수한다.
- 네트워크/응답 오류는 최대 3회, 실패 후 20초·40초 뒤 재시도한다. 한 번 분석해서 조건이 모호한 결과를 얻으면 확인필요로 표시한다. 재시도를 모두 소진해도 확인필요와 원인을 표시한다.
- 분석 전·진행 중의 공고와 지원내역은 **AI 분석 중**이다. 미분석 공고의 직접 지원도 준비 상태로 보관하며, 분석 중 실패 안내 메일은 보내지 않는다.
- 분석 완료 시 대기 중인 지원내역을 다시 준비한다. 직접 지원은 검수 후 사용자가 명시적으로 발송해야 하며, 자동 지원은 기존 동의·필터·발송 방식과 테스트 수신처 정책을 따른다.
- 열려 있는 공고 목록·상세·지원 모달은 5초 간격으로 분석 결과를 확인해 갱신한다. 분석 완료 이후 공고 조회는 종료한다.
- 이전 구현에서 분석 전에 확인필요가 된, 아직 편집·발송하지 않은 직접 지원내역만 준비 상태로 복구한다. 기존 공고를 지원현황에 일괄 추가하지 않는다.

## 2026-09-17 목록 메뉴와 삭제
